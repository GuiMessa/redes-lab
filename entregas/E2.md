# Entrega 2 — O roteador e o encapsulamento

## O que está em jogo

<walkthrough-tutorial-duration duration="75"></walkthrough-tutorial-duration>

Esta é a entrega mais importante do semestre. Não porque é a mais difícil, mas
porque é a única em que vocês vão **ver** o modelo de camadas acontecer num
pacote de verdade, em vez de olhar um desenho dele.

A pergunta que vocês vão responder com evidência: quando um pacote atravessa um
roteador, **o que muda nele e o que não muda?**

**Vale 1,4** · **Prazo: semana 9**

## Suba e olhe o vermelho

```bash
make up E=2 && make verificar E=2
```

O roteador já está no ar, com uma perna em cada segmento e o repasse IP
ligado — a verificação confirma isso em verde. Mesmo assim nada atravessa.

Pense antes de mexer: se o roteador está pronto e ligado nos dois lados, **por
que o host não chega do outro lado?**

## Sua tarefa

<walkthrough-editor-open-file filePath="e2-roteador/docker-compose.yml">
abrir o docker-compose.yml
</walkthrough-editor-open-file>

Falta rota. Um host só sabe falar com quem está na própria sub-rede; para o
resto, alguém precisa dizer por onde ir.

Acrescentem, **dentro do `command`** de `host-a1` e de `host-b1`, a rota para a
sub-rede do outro lado, apontando para o roteador. A forma é:

```
ip route add <rede-de-destino> via <endereço-do-roteador-no-meu-segmento>
```

Duas regras que valem nota:

* escrevam no `docker-compose.yml`, não no terminal. Rota digitada à mão some
  quando o contêiner reinicia; o que está no arquivo sobrevive e é reproduzível
  na máquina do professor. É essa a diferença entre configurar e documentar.
* **não toquem em `host-a2`.** Ele existe para ficar sem rota. Ele é o grupo de
  controle: mesma máquina, mesma rede, só muda a configuração. Sem ele, "o ping
  passou" não prova que foi a rota que fez a diferença.

## Prove

```bash
make verificar E=2
```

Além do ping, o roteiro faz duas medidas que são o coração da entrega:

**O TTL.** O pacote sai com TTL 64 e chega com 63. Um salto foi consumido — é a
assinatura de que houve roteamento, e não dois hosts no mesmo fio.

**As duas capturas.** O roteiro captura o mesmo ping nas duas pernas do
roteador ao mesmo tempo e compara. Vocês vão ver, impresso lado a lado:

* o **endereço IP de origem é idêntico** nos dois lados;
* o **endereço MAC de origem é diferente**.

É isso o encapsulamento. A carga de camada 3 atravessa a rede inteira sem
mudar; o quadro de camada 2 é jogado fora e refeito em cada enlace. O simulador
de camadas desenha isso; aqui é o pacote de vocês dizendo o mesmo.

Ao final, `perna-a.pcap` e `perna-b.pcap` ficam na pasta. **Abram os dois no
Wireshark** e localizem, na tela, o campo que mudou e o que não mudou.

## Entregue

```bash
make evidencias E=2
git add -A && git commit -m "Entrega 2" && git push
```

No `README.md`, escrevam um parágrafo respondendo: *por que o MAC precisa mudar
se o IP não muda?* É a pergunta da prova.

## Como é corrigido

| O quê | Pontos |
|---|---|
| `make verificar E=2` verde, com o controle `host-a2` intacto | 0,5 |
| Rotas no `docker-compose.yml` (não digitadas no terminal) | 0,2 |
| Os dois `.pcap` no repositório | 0,2 |
| Print do Wireshark apontando o campo que mudou e o que não mudou | 0,2 |
| Parágrafo explicando por que o MAC muda e o IP não | 0,3 |
